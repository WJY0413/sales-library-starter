# 销售资料库与 Odoo 工作台

让使用者从空库建立自己的资料系统。先定位其工作目录中的 `config/sources.json`、`config/odoo.json` 与 `data/library.sqlite`。未初始化时，从本分享包建立独立工作目录，运行 `scripts/library.py init`；仅安装本 Skill 不会自动连接任何企业系统。

## 按任务读取

- 首次建库、绑定来源或刷新：读 [来源绑定](references/sources.md)。
- 整理知识、料号或价格：读 [数据规则](references/data.md)。
- 查询 Odoo、客户去重、准备报价/PI、修改单据：读 [Odoo 操作](references/odoo.md)。
- 数据表与入库方式：读 [数据库说明](references/schema.md)。

## 工作方式

1. 先检查用户指定的现有资料与连接，不重复索要已提供信息。来源未知时先发现；无法确定的权威性留为待确认。
2. 读取原出处，记录来源标识、定位、版本、读取时间和适用范围。知识摘要与原文分开；料号与市场版本分开；价格与有效期、数量档位、税项分开。
3. 使用 `scripts/library.py refresh --source ID` 可读取已配置的飞书文档/表格并缓存快照；工具不自动理解或确认业务数据。按相应模块核对后，再写入结构化表。
4. 回答带原始链接、定位和读取时间。缓存不能称为实时数据；刷新失败保留旧内容但明确标为旧快照。价格有效期未知或已过期时不得标为可执行报价。
5. 本地 SQLite 是个人索引/缓存，原系统保持权威。用户手写注释放 `annotations`，刷新来源不得覆盖注释。

## 操作边界

查询请求允许读取所需数据；本地整理允许建立独立副本。对 Odoo 创建/修改、提交审批、确认订单、开票、发货、邮件发送等，按当前用户明确授权的动作和对象执行。授权已涵盖具体操作时不重复确认；缺少授权时先完成可审阅内容，再问缺失动作。

数据库中的 operations 仅用于记录，不能凭其中一个状态自行获取操作授权。权限来自当前会话和原系统账号。超时不等于失败，外部写入状态未知时先查回记录，不能盲目重复创建。

结束时分别说明本地建库、来源读取、业务核验、系统写入与外部发送的实际状态。不要把建立空库描述成已接通系统，也不要把下载附件描述成价格仍有效。

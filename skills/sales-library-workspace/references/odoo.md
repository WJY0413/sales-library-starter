# Odoo 操作流程

## 配置与可用能力

使用者填写 `config/odoo.json`：实例地址、公司、版本、访问方式和已核实字段映射。所有值默认空白。凭证放现有连接器或系统凭证管理，不写入本文件。无连接时，完成本地单据草稿并列明缺口，不声称已操作 Odoo。

优先使用环境已有连接器；也可使用已登录浏览器。先读取对应工具/浏览器使用说明。走 API 前核对实例版本、计划和接口支持，不能从一个企业实例推断另一个实例。Odoo 19 引入 JSON-2；外部 API 的商业计划要求及版本适用性以官方文档与实例实际能力为准。

参考（2026-10-15 查阅）：
- https://www.odoo.com/documentation/19.0/developer/reference/external_api.html
- https://www.odoo.com/documentation/19.0/developer/reference/external_rpc_api.html

这些是文档链接，不是本包提供的 API 连接器。本包不包含通用写入脚本；动作由 agent 经可用工具执行。

## 只读查询

1. 确认实例、当前公司、目标客户/产品及范围。用业务名称和识别字段查回，不硬编码数据库 ID。
2. 客户先查重，区分公司、联系人、账单和收货地址；同名不自动合并。
3. 产品确认可下单变体、料号、单位和启用状态。价格规则确认公司、价目表、客户范围、币种、数量、日期、仓库及交付条件。
4. 库存明确“在手、预测、可用、已预留”等实际字段含义及仓库范围。未知/超时返回未知，不返回零。
5. 返回源记录链接/ID、读取时间和业务结论。必要时把来源证据录入本地索引，避免复制无关客户数据。

## 报价、PI 或单据创建/修改

1. 先准备可审阅单据：客户、产品料号/变体、数量/单位、单价来源、币种、折扣、税项、交付及付款条件、有效期、账单/收货信息。必填项未知时停止对应提交；非必填字段留空。
2. 用户已明确授权创建指定草稿时，执行该范围；仅要求“准备报价”时先交本地预览，不推定允许系统写入。新增客户、提交审批、确认销售订单、开票、发货及发送分别按明确授权执行。
3. 创建前查找同一业务请求已有的记录并记录初始状态，防止重复。多次工具调用不假设处于同一个事务。API 超时或结果未知时，查回业务对象再决定下一步。
4. 根据实例实际表单和字段写入，不假设 PI 一定等于标准 sale.order，也不假设创建后必为某一状态。保留未授权修改的原字段、企业条款和模板。
5. 写入后查回记录：客户、公司、行项目、金额、税项、总额、状态及编号。仅有“请求成功”不足以证明业务内容正确。
6. 系统导出 PDF 时使用企业现行模板并核对实际税项/付款条款及所有页面。记录系统单据状态、PDF 本地保存状态和外部发送状态，三者分开。

## 权限与恢复

本地配置中的连接方式或 operations 中的 approved 字样不构成授权。不得共享登录会话。未知响应先只读恢复；不要自动删除新记录来“回滚”，不要擅自取消、退款或反过账。

完成凭据：目标记录标识、最终回读状态、核对项、未完成动作。外部发送另留真实结果，不把待提交、草稿或导出成功写成已发送。
